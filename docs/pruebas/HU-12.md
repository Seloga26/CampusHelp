## Funcionalidad

- `GET /api/casos/:id?usuario_id=`: detalle con datos, fechas y atenciones.
- Solicitante activo: solo sus propios casos. Agente, Validador y Administrador
  activos: cualquier caso. Usuario inactivo/inexistente: 403. Los permisos se
  verifican antes de leer atenciones.
- IDs enteros positivos válidos, incluidos como texto numérico en la URL;
  valores como `1e1` o `1.0` se rechazan sin convertirlos primero.
- Atenciones en orden descendente de fecha/id; la más reciente es la solución
  vigente y las anteriores se conservan. Se reutilizan los repositorios de
  casos y atenciones existentes; no cambia el esquema de MySQL.
- `/detalle.html?id=`: datos, agente, cuatro fechas, diagnóstico/solución y
  mensajes para casos sin agente o sin solución. Acceso desde Mis casos,
  bandeja y menús, con enlace al historial.
- Consulta de solo lectura. Los datos se construyen con `textContent`; al
  cambiar de usuario o fallar la consulta se limpian. Las respuestas de una
  consulta anterior se descartan, incluso si llegan después del cambio de rol.

Las pruebas crean el caso mediante la API real, incluyendo una devolución
de HU-07 y la segunda atención. No insertan una solución o asignación
artificial para suplir las dependencias. Comparan las tablas `caso`, `atencion`
y `historial` antes/después de consultas para confirmar que siguen intactas.

Para CP-41, Bruno recibe 403 y el resultado se limpia. Una prueba demora la
respuesta autorizada de Ana, cambia a Bruno y comprueba que la respuesta
tardía no revela datos. CP-42 confirma Sin asignar y Aún no hay una solución
registrada. CP-43 confirma la solución vigente y la anterior conservada.

Se usan bases `campushelp_hu12_test_*` y `campushelp_hu12_browser_test_*` y
perfiles temporales de Chrome, eliminados al terminar. No se ejecuta `db:init`
ni se modifica la base `campushelp` de la aplicación.

## Repetir las pruebas

Requiere MySQL y credenciales de `.env` con permiso para bases temporales,
Chrome/Edge y Node.js 22+ para navegador.

```powershell
$env:CAMPUSHELP_TEST_MYSQL = '1'
$env:CAMPUSHELP_TEST_BROWSER = '1'
try { npm.cmd test } finally {
  Remove-Item Env:CAMPUSHELP_TEST_MYSQL
  Remove-Item Env:CAMPUSHELP_TEST_BROWSER
}
```

Para ejecutar solo esta historia, con esas variables activas:

```powershell
node --test tests/services/consultarDetalle.test.js tests/api/detalle.test.js tests/detalle.mysql.test.js tests/browser/detalle.mysql.test.js
```

Para revisar la página, iniciar la aplicación y seleccionar a Ana en Mis casos.
Abrir **Ver detalle** de un caso con atenciones; cambiar a Bruno para comprobar
el rechazo y luego a un agente para ver el acceso interno. Consultar un caso
Pendiente sin solución y uno con varias atenciones para revisar los mensajes
y el orden de las soluciones. Los casos deben existir en la base configurada.
