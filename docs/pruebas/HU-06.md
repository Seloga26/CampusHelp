## Alcance implementado

- `src/services/casos/registrarAtencion.js`: valida IDs y textos, agente activo,
  asignación y estado En atención. Bloquea la fila del caso mientras guarda
  atención e historial en la transacción común. No cambia el estado.
- `src/repositories/atencionesRepository.js`: `crear()` devuelve la fila con la
  fecha real de MySQL; `contarPorCaso()` cuenta solo las atenciones del caso.
- `src/services/casos/cambiarEstado.js`: devuelve 409 al enviar a En validación
  sin atención registrada. Usa el mismo bloqueo de fila que el registro de
  atención para coordinar peticiones concurrentes.
- `/atender.html?id=<caso>` y `public/js/atender.js`: formulario independiente,
  selector de agentes, mínimo de 10 caracteres tras trim, errores visibles,
  conservación del texto ante errores y protección frente a doble clic.
- `POST /api/casos/:id/atencion`: ruta y contenedor del Sprint 2 reutilizados.

Cada atención genera un evento "Atención registrada" con autor y fecha. Los
campos de estado del evento quedan NULL porque esta operación no cambia el
estado. Una nueva atención no modifica las anteriores.

## Repetir las pruebas

```powershell
npm.cmd test
$env:CAMPUSHELP_TEST_MYSQL = '1'
$env:CAMPUSHELP_TEST_BROWSER = '1'
try { npm.cmd test } finally {
  Remove-Item Env:CAMPUSHELP_TEST_MYSQL
  Remove-Item Env:CAMPUSHELP_TEST_BROWSER
}
```

La primera ejecución pasa **97 pruebas** y omite cuatro suites optativas:
dos MySQL y dos de navegador con MySQL. La segunda usa las credenciales de
`.env`; necesita permisos para crear bases temporales y triggers. La prueba
de navegador requiere Node.js 22+ y Chrome o Edge; `CAMPUSHELP_BROWSER`
permite indicar el ejecutable. La aplicación continúa admitiendo Node.js 18+.
Para ejecutar solo el navegador de HU-06, activar `CAMPUSHELP_TEST_BROWSER=1`
y ejecutar `node --test tests/browser/atencion.mysql.test.js`.

Para probar manualmente el formulario, usar un caso En atención y asignado a
un agente en una base de pruebas. Iniciar `npm.cmd start`, abrir
`http://localhost:3000/atender.html?id=<caso>`, elegir ese agente y guardar
diagnóstico y solución. Comprobar `atencion` e `historial`; el caso permanece
En atención y posteriormente puede enviarse a En validación con HU-05.

## Validación adicional de HU-06 (2026-10-09)

`tests/browser/atencion.mysql.test.js` añade siete escenarios, además de su
suite principal, usando Express, Chrome y **MySQL 8.0.46**:

- ID desde el enlace y rechazo de textos con menos de 10 caracteres tras trim,
  sin enviar peticiones ni perder lo escrito.
- CP-20: error 403 al seleccionar otro agente, sin escrituras y con textos
  conservados para reintentar al elegir el agente asignado.
- CP-07: doble clic genera una sola petición, atención e historial con autor
  y fecha. Los controles se deshabilitan mientras guarda, el estado permanece
  En atención y los textos se limpian únicamente tras confirmar el éxito.
- Un trigger de MySQL provoca un fallo real del historial: la API responde
  500, hace rollback, conserva los textos y permite reintentar. La segunda
  atención no modifica la primera.
- CP-21: una solicitud de servicio En análisis muestra error 409 sin atención
  ni historial; después de cambiar a En atención, se registra correctamente.
  Los escenarios de formulario incluyen un incidente de Red y una solicitud de Cuentas.
- Regreso a la bandeja, envío a En validación y rechazo de otra atención
  después de validar, conservando todos los datos confirmados.
- Sin agentes activos, formulario deshabilitado; ID inválido de URL ignorado.

La suite de bandeja también comprueba CP-22: error visible sin solución y
envío exitoso después de registrar atención del propio caso. La suite MySQL
de HU-06 conserva los escenarios de concurrencia, rollback y persistencia
tras reiniciar servidor y conexiones.
