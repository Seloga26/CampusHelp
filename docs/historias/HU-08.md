# HU-08 — Consultar el historial de un caso

## Identificación

- **Tipo de caso relacionado:** Incidente y Solicitud de servicio
- **Área / Categoría:** Todas
- **Prioridad:** P2
- **Story Points:** 5
- **Dependencias:** HU-05 (`casosRepository.buscarPorId`, Sprint 1). Los eventos los registran HU-01 y HU-05 (Sprint 1) y HU-04, HU-06 y HU-07 (Sprint 2).
- **Responsable:** Sebastian

## Historia

Como **usuario autorizado**, quiero **consultar el historial**, para **conocer lo ocurrido**.

## Reglas de negocio

1. **Usuarios autorizados:** Agente, Validador y Administrador ven el historial de cualquier caso; un Solicitante solo el de **sus** casos.
2. Los eventos se muestran en orden cronológico (del más antiguo al más reciente).
3. Cada evento muestra: fecha, evento, estado anterior → estado nuevo (si hubo cambio) y el usuario que lo hizo con su rol.
4. Es solo lectura: el historial no se edita ni se borra.

## Criterios de aceptación

**Escenario 1 — Historial completo (CP-26)**
- Given un caso registrado, asignado y pasado a En análisis
- When un agente consulta su historial
- Then ve 3 eventos en orden: "Caso registrado", "Caso asignado", "Cambio de estado" (Pendiente → En análisis), con usuario y fecha

**Escenario 2 — Solicitante ajeno (CP-27)**
- Given un caso registrado por Ana
- When Bruno (Solicitante) consulta su historial
- Then el sistema responde 403

**Escenario 3 — Caso inexistente (CP-28)**
- Given un id de caso que no existe
- When se consulta el historial
- Then el sistema responde 404

## Contrato de API

```json
// GET /api/casos/:id/historial?usuario_id=3
// 200 →
[{ "id": 1, "evento": "Caso registrado", "estado_anterior": null, "estado_nuevo": "Pendiente",
   "usuario": "Ana Solicitante", "rol": "Solicitante", "fecha": "2026-10-08 09:30:00" }]
// 400 usuario_id inválido | 403 sin permiso | 404 caso no existe
```

## Implementación

- **Orden:** `ORDER BY h.fecha, h.id`. La columna `fecha` es `DATETIME` sin fracciones, así que varios eventos del mismo segundo (asignar y avanzar, por ejemplo) se ordenan por el id de inserción.
- **Permisos:** un usuario inexistente o inactivo recibe 403. El 404 se comprueba antes del permiso del solicitante.
- **Sin transacción:** es una consulta de solo lectura.
- **Seguridad en la página:** los eventos se pintan con `textContent`, nunca como HTML.
