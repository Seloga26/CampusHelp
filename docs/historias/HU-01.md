# HU-01 — Registrar incidente o solicitud

Ejemplo de refinamiento tomado del Taller (sección 6). Revísenlo en el primer Refinement.

## Identificación

- **Tipo de caso relacionado:** Incidente y Solicitud de servicio
- **Área / Categoría:** Todas
- **Prioridad:** P1
- **Story Points:** 5
- **Dependencias:** ninguna
- **Responsable:**

## Historia

Como **solicitante**, quiero **registrar un incidente o solicitud de servicio tecnológico**, para **solicitar atención de la mesa de servicios**.

## Reglas de negocio

1. Tipo obligatorio: Incidente o Solicitud de servicio.
2. Área y categoría obligatorias; la categoría debe pertenecer al área elegida.
3. Título obligatorio.
4. Descripción con mínimo 10 caracteres.
5. Prioridad P1, P2 o P3.
6. Fecha de creación automática.
7. Estado inicial: Pendiente.

## Criterios de aceptación

**Escenario 1 — Registro válido**
- Given un solicitante con todos los campos obligatorios diligenciados
- When guarda el caso
- Then se genera un ID, el caso queda persistido en estado Pendiente y aparece en la bandeja

**Escenario 2 — Descripción insuficiente**
- Given un solicitante que deja la descripción vacía o con menos de 10 caracteres
- When intenta guardar
- Then el sistema rechaza el registro e indica el error

**Escenario 3 — Persistencia**
- Given un caso registrado
- When se reinicia la aplicación
- Then el caso sigue disponible con sus datos
