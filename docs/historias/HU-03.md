# HU-03 — Bandeja de casos pendientes

## Identificación

- **Tipo de caso relacionado:** Incidente y Solicitud de servicio
- **Área / Categoría:** Todas
- **Prioridad:** P1
- **Story Points:** 3
- **Dependencias:** HU-01 para tener casos reales. Se mitiga con la tarea T0 (casos de ejemplo en `seed.sql`), que también es de esta historia.
- **Responsable:** Keyla (propuesto)

## Historia

Como **agente**, quiero **visualizar la bandeja de casos pendientes**, para **seleccionar trabajo**.

## Reglas de negocio

1. La bandeja muestra todos los casos que **no** están Cerrada (Pendiente, En análisis, En atención, En validación).
2. Orden: prioridad (P1 → P2 → P3) y, dentro de la misma prioridad, el más antiguo primero. Así lo urgente y lo que más ha esperado queda arriba.
3. Cada caso muestra: ID, título, tipo, área, categoría, prioridad, estado, solicitante, agente asignado (o "Sin asignar") y fecha de creación.
4. Se accede actuando como un usuario con rol Agente.

## Criterios de aceptación

**Escenario 1 — Orden de la bandeja**
- Given casos P3 antiguo, P1 reciente y P1 antiguo, todos sin cerrar
- When el agente abre la bandeja
- Then los ve en este orden: P1 antiguo, P1 reciente, P3 antiguo

**Escenario 2 — Casos cerrados no aparecen**
- Given un caso en estado Cerrada
- When el agente abre la bandeja
- Then ese caso no aparece

**Escenario 3 — Caso nuevo**
- Given un solicitante que acaba de registrar un caso (HU-01)
- When el agente abre o recarga la bandeja
- Then el caso aparece en estado Pendiente y "Sin asignar"

## Decisiones de refinamiento

- **"Pendientes" no significa solo estado Pendiente:** el agente necesita ver todo el trabajo abierto para continuar lo que ya empezó. Por eso se excluyen solo los casos cerrados.
- **Filtros por estado, tipo, área, etc.:** quedan para HU-09 (Sprint 3).
